# burlaka — учёт освоения строительного проекта

Одностраничное приложение (без бэкенда и сборки) для генподрядчика: учёт
работ по проекту в разрезе видов работ, договоров с субподрядчиками,
закупленных материалов и фактического выполнения — с динамикой освоения
проекта во времени.

## Модель данных

- **Проект** — объект строительства для конкретного заказчика.
- **Вид работ** (например «Внутреннее СКС», «Фасадные работы») — раздел
  сметы со своей договорной ценой с заказчиком (доходная часть). Внутри
  раздела:
  - **Договоры с субподрядчиками** — название/подрядчик, сумма, дата, а также
    необязательная расшифровка договорной цены построчно (наименование,
    объём, расценка — вводятся без НДС). Если позиции добавлены, сумма
    договора считается как сумма всех позиций плюс НДС по указанной ставке
    (по умолчанию 20%, можно изменить для каждого договора). В таблице
    расшифровка показывается отдельной аккуратной табличкой по колонкам
    (наименование/объём/расценка/сумма), а расценка и сумма в ней — уже
    с учётом НДС;
  - **Закупленные материалы** — название/поставщик, количество (числом и
    единицей измерения — например «100 мешок»), сумма закупки, дата, а также
    остаток на складе (закупленное количество минус списанное по актам);
  - **Выполнение работ (акты)** — дата, сумма выполненных работ, комментарий,
    и список материалов, списанных по этому акту (необязательно); вносится
    ежедневно или по мере подписания актов, нарастающим итогом.

### Списание материалов по актам

В форме акта («Выполнение работ») можно указать, какие из уже закупленных
материалов и в каком количестве подрядчик использовал согласно этому акту.
Стоимость списания приложение считает само: количество из акта × закупочная
цена за единицу (сумма закупки ÷ закупленное количество). Остаток материала
на складе (в таблице «Закупленные материалы») уменьшается автоматически на
списанное количество по всем актам. Если списано больше, чем было закуплено,
остаток уходит в минус и подсвечивается красным — это сигнал проверить акты
или закупку.

Это не меняет общую сумму «Затраты» по разделу — материалы по-прежнему
учитываются в затратах в момент закупки (по кассовому принципу). Списание по
актам определяет, сколько материала физически ушло в работу и сколько ещё
осталось на складе.

Сумма, которая вводится в акте («Сумма работ») — это стоимость только самой
работы, без материалов (материалы генподрядчик закупает отдельно, поэтому
подрядчик выставляет акт только на подряд). «Освоено» по каждому акту и по
разделу в целом приложение считает как сумму работ **плюс** стоимость
списанных по этому акту материалов — так «Освоено» отражает полную ценность
выполненного, а не только подрядную часть. В таблице «Выполнение работ»
отдельными колонками показаны «Работы», «Материалы» и «Итого» по каждому
акту (наведите курсор на сумму материалов, чтобы увидеть, какие именно
материалы и в каком количестве туда вошли), а в карточках «Освоено» —
подпись с разбивкой на работы и материалы.

## Что показывает приложение

- по каждому виду работ: бюджет (доход), затраты (договоры + материалы),
  освоено (сумма актов), маржу и % выполнения;
- по проекту в целом — то же самое агрегированно, плюс график динамики
  освоения: заработано и потрачено нарастающим итогом по датам, с линией
  ориентира на договорную цену с заказчиком;
- все данные сохраняются в `localStorage` браузера — сервер не требуется.

## Распознавание материалов по фото

Кнопка «📷 По фото» в разделе «Закупленные материалы» позволяет сфотографировать
(или загрузить) расходную накладную/счёт — приложение отправляет фото
в Claude (Anthropic API) с вашего личного API-ключа и предзаполняет
форму материала (название, поставщик, количество, сумма, дата). Перед
сохранением данные всегда можно проверить и поправить.

Ключ вводится один раз в настройках (значок ⚙ рядом со списком проектов) и
хранится только в `localStorage` браузера. Без ключа кнопка «По фото» откроет
настройки для его ввода.

### Нужен сервер-посредник (прокси)

Браузер **не может** обращаться к `api.anthropic.com` напрямую с обычного
сайта — Anthropic не присылает CORS-заголовок, разрешающий такие запросы, и
браузер их блокирует (ошибка `Failed to fetch`). Это ограничение всех сайтов,
не что-то специфичное для этого приложения.

Поэтому запросы идут через маленький бесплатный прокси на Cloudflare Workers,
который просто пересылает запрос в api.anthropic.com и добавляет CORS-
заголовки к ответу — он не хранит и не читает ваш ключ. Скрипт прокси лежит
в [`cloudflare-worker.js`](./cloudflare-worker.js), в начале файла — пошаговая
инструкция по развёртыванию (регистрация на dash.cloudflare.com, создание
Worker, вставка кода — без установки чего-либо на компьютер).

После развёртывания адрес воркера (вида `https://имя.логин.workers.dev`)
нужно один раз указать в настройках приложения (значок ⚙) → «Адрес сервера-
посредника (прокси)», вместе с API-ключом. Без указанного адреса прокси все
три сценария распознавания (фото, договор из файла, накладная из файла)
покажут понятную ошибку с просьбой заполнить настройки.

## Загрузка договоров и накладных из файла

- **Договоры**: кнопка «📄 Из файла» в разделе «Договоры с субподрядчиками»
  принимает PDF или фото/скан договора и предзаполняет название субподрядчика,
  сумму, дату и краткую суть договора; если в файле есть смета или
  спецификация — построчная расшифровка договорной цены (наименование, объём,
  расценка) — она тоже распознаётся и подставляется в форму. Перед
  сохранением форму можно проверить и поправить.
- **Материалы (массово)**: кнопка «📁 Из накладной» в разделе «Закупленные
  материалы» принимает PDF, изображение, Excel (.xlsx/.xls) или Word (.docx) с
  накладной/счётом/спецификацией и распознаёт сразу список позиций — открывается
  таблица с предзаполненными строками (название, количество, единица измерения,
  сумма) и общей датой документа, где можно отредактировать, удалить лишние или
  добавить строки вручную перед добавлением всех позиций в проект.
- **Акты выполненных работ**: кнопка «📄 Из акта» в разделе «Выполнение работ»
  принимает PDF или фото/скан акта и предзаполняет сумму выполненных работ,
  дату, краткое описание и список использованных материалов с количеством.
  Если в одном файле несколько актов (например, скан пачки актов за разные
  даты), приложение распознаёт их все и показывает по одному за раз —
  «Акт 1 из 3», «Акт 2 из 3» и т.д.; сохранили один — тут же открывается
  следующий, отмена одного акта не отменяет остальные, а просто пропускает
  его и переходит к следующему. Каждый материал из акта приложение пытается
  сопоставить с уже закупленным по названию — намеренно нестрого: сначала
  ищется точное совпадение, затем совпадение по подстроке, а если и это не
  нашлось — материал, с которым у названия из акта больше всего общих слов
  (без учёта порядка слов, знаков препинания и написания на укр./рус.). Так
  «Щебень» из акта найдёт нужную позицию на складе, даже если там она
  записана как «Щебень фр. 20-40мм». Если общих слов не нашлось вовсе —
  строка остаётся с пометкой «не найдено» для ручного выбора. Перед сохранением каждого акта
  всё можно проверить и поправить.

Все сценарии используют тот же личный API-ключ Anthropic и тот же прокси из
настроек, что и распознавание по фото. Для
чтения Excel и Word используются библиотеки SheetJS и Mammoth.js, которые
подключаются с CDN — для этих двух форматов при открытии приложения нужен
доступ в интернет (PDF и фото обрабатываются напрямую через Claude и не
требуют этих библиотек).

## Запуск

Сборка не требуется. Достаточно открыть `index.html` в браузере либо
поднять любой статический сервер:

```bash
python3 -m http.server 8000
```

и перейти на `http://localhost:8000`.

## Структура

- `index.html` — разметка страницы и диалоговые окна создания/редактирования;
- `style.css` — стили интерфейса (поддерживается светлая и тёмная тема);
- `app.js` — модель данных, расчёты (затраты/освоение/маржа), рендер
  экранов и график динамики освоения;
- `cloudflare-worker.js` — скрипт прокси для распознавания по фото/файлам
  (см. «Нужен сервер-посредник (прокси)» выше).
